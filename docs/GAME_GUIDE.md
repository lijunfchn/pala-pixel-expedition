# 圣犬帕拉 · 微光远征：游戏与开发说明

## 1. 版本定位

这是受《Paladog / 圣犬帕拉》启发、围绕“英雄带兵推进”设计的原创像素单机游戏。目标是在电脑上直接打开即可游玩，保留资源管理、部队搭配、英雄站位与施法救场的乐趣。

本项目使用自己编写的 Canvas 绘制与 Web Audio 合成内容，没有提取原作素材，也不是原作的官方版本。关卡、平衡数值和画面均以当前代码为准。

## 2. 启动与环境

### 最简单的启动方式

1. 将项目放在电脑的普通文件夹中，保留原有目录结构。
2. Windows 用户双击根目录的 `启动游戏.cmd`；也可以直接用浏览器打开 `index.html`。
3. 在游戏界面选择战役关卡，或点击“开始生存”。

推荐现代桌面浏览器 Edge、Chrome 或 Firefox。无需安装第三方包、无需联网。首次播放声音前需要点击页面；静音状态下仍可正常游玩。

### 可选：本地开发服务器

安装 Node.js 22 或更新版本，在项目根目录执行 `npm start`，再打开 <http://127.0.0.1:4173>。不需要 `npm install`。

如果端口占用，PowerShell 中可以先执行 `$env:PORT = '4174'` 再执行 `npm start`，访问相应端口。服务器只监听 `127.0.0.1`，用于本机预览。

直接打开文件与通过服务器打开会形成不同的浏览器存储来源；二者的存档不一定共享。

## 4. 战斗目标与策略

战役的胜利目标是摧毁敌方据点，英雄阵亡则失败。首领关的据点带有护盾，必须先击败暗影领主才能造成据点伤害。据点血量首次降至一半时会触发一次守军增援；即使大招跨过半血线，也会先留下半血让援军登场。英雄可以自由走位，并自动攻击身边的敌人；伙伴会自行向敌人推进并攻击。把英雄放在能支援前线且不容易受到集火的位置。

**食物用于出兵，魔法用于施法。** 资源会随战斗恢复，出兵不是越快越好：先建立能站住的前排，再补充远程单位，在敌人集中或前线危急时用技能创造优势。

英雄附近的支援光环会提升伙伴的攻击速度和伤害，并减少其承受的伤害。不要把所有单位都当作消耗品；保持部队存活，能让新召唤的伙伴继续积累成完整军团。

按空格、Esc 或右上方暂停按钮可以暂停。切换窗口或浏览器标签页时，战斗会自动暂停，返回后需选择继续；战斗中打开“冒险手册”也会暂停，关闭手册后回到打开前的状态。

点击顶部“远征地图”或标题可以收队回营。进行中的战斗会先要求确认，收队不会获得本次奖励，已有升级与通关进度会保留。

## 5. 战役与伙伴

战役包含 6 个章节、24 个关卡，按顺序逐步开放。每关的敌人组合、出场节奏和难度围绕推进战展开，后续关卡需要更完整的部队与升级支持。完成首领关的解除护盾条件后，或在普通关卡中，击破据点即能获胜，不必等所有波次结束。

| 伙伴 | 解锁时间 | 战术作用 |
| --- | --- | --- |
| 坚果剑士（鼠） | 第 1 关起 | 12 食物；低成本近战前排，不能攻击飞行单位 |
| 苜蓿游侠（兔） | 第 1 关起 | 24 食物；远程弓手，可以攻击飞行单位 |
| 松果重卫（熊） | 第 3 关起 | 44 食物；高生命近战承伤单位，不能攻击飞行单位 |
| 星火法师（狐） | 第 6 关起 | 58 食物；范围魔法攻击，可以攻击飞行单位 |
| 松果投手（松鼠） | 第 8 关起 | 39 食物；爆裂松果的范围攻击，适合清理密集敌人 |
| 荆刺守卫（刺猬） | 第 11 关起 | 48 食物；有减伤护甲，受到近战攻击时反弹伤害 |
| 月羽医师（猫头鹰） | 第 14 关起 | 55 食物；跟随前线，定期治疗受伤友军 |
| 破晓野猪 | 第 18 关起 | 72 食物；高速冲锋，蓄力攻击可击退地面敌人 |

兵种加入后会一直保留，重访早期关卡时也能召唤已解锁的伙伴。场上最多同时拥有 28 个伙伴；英雄不计入这个数量。

点击顶部“远征图鉴”可以在兵种图鉴与怪物图鉴之间切换。兵种条目列出解锁关卡、食物消耗、生命、攻击或治疗量与冷却；怪物条目列出首次出现关卡、基础属性与应对建议。高关卡敌人的实际属性会在基础值上提高。战斗中打开图鉴会暂停游戏，关闭后继续。

| 魔法 | 按键 | 消耗 / 冷却 | 用途 |
| --- | --- | --- | --- |
| 圣光雷击 | J | 22 魔法 / 5.5 秒 | 自动选择有效目标，造成范围伤害；可攻击据点 |
| 生命祷言 | K | 30 魔法 / 11 秒 | 治疗英雄和附近的受伤伙伴 |
| 寒霜领域 | L | 34 魔法 / 14 秒 | 造成范围伤害，并使命中的敌人减速 7 秒 |

没有有效目标时，攻击魔法不会扣除资源；附近角色满血时，治疗也不会消耗魔法。寒霜领域不能以据点为目标。实际消耗与当前冷却也可在界面查看。

敌人共有 12 类：荒骨兵、幽苔史莱姆、暮色蝠、石甲巨兽、枯枝巫师、暗影领主、骸骨射手、寒雾幽影、夜袭猎犬、铁壳守卫、灰烬祭司与裂火虫。蝙蝠和幽影会飞行，须用英雄、游侠、法师或投手应对。射手会从远处施压，猎犬快速突破，铁壳守卫有护甲，灰烬祭司会治疗同伴，裂火虫死亡时会爆炸。巫师还会召唤援军。第 3、6、9、12、16、20、24 关是首领关：领主会在最后一波登场，如果提前攻击带护盾的据点，则会提前引出领主。

过关星级取决于获胜时英雄剩余生命：至少 60% 获得三星，至少 30% 获得二星，其余获胜情况获得一星。谨慎站位和及时治疗能帮助争取更高星级。

### 无尽生存

从营地的“无尽生存”入口随时开始独立挑战，不需要先通关战役。这里没有可摧毁的敌方据点：清除一波敌军后，约三秒后开始下一波；敌军种类、数量和强度随波次提升，每五波出现暗影领主。全部八种伙伴在生存模式中可用，已装备的权杖、戒指与营地升级会带入战斗。

每守住三波，会暂停战斗并给出三项随机祝福，选一项才能继续。生命祈愿提高生命上限并治疗；丰收补给提升食物上限与恢复；星辉冥想提升魔法上限与恢复；勇气号角提高帕拉及当前、后续伙伴的伤害。祝福可重复选择并叠加，但只在当前挑战中有效。

帕拉阵亡后，按**已守住的完整波次**与击退敌人数结算金币，最高奖励为 600 金币；营地会保存最佳守住波次和相应击退数。生存成绩不解锁关卡，也不会改写战役星级和通关时间。主动收队不会结算这次挑战；刷新页面也不会恢复进行中的挑战。

资料核对：原作手机版有剧情战役与生存挑战，Flash 版则只有战役。剧情关卡内部还出现过护送马车、多战线和守波次等变体；2011 年更新又加入以 Darkdog 为主角的模式和三个小游戏。本项目当前实现战役与独立生存；无尽生存沿用“逐波挑战、随机强化”的核心思路，采用原创波次、祝福、数值和美术，并非逐项复刻。[GameFAQs 的 2012 年生存模式指南](https://gamefaqs.gamespot.com/iphone/620153-paladog/faqs/65417)；[AyumiLove 的关卡玩法指南](https://ayumilove.net/paladog-walkthrough-guide/)；[Pocket Gamer 的 Darkdog 更新报道](https://www.pocketgamer.com/paladog/gold-award-winning-iphone-castle-defence-game-paladog-updated-with-extra-playabl/)。

## 6. 装备、营地升级与存档

点击顶部“装备与强化”，即可用金币为帕拉购买权杖和戒指。每类只能装备一件；购买后永久拥有，之后可免费切换，下一场战斗开始时生效。旧存档自动获得基础装备，金币和关卡进度不会重置。

| 装备 | 解锁 | 价格 | 效果 |
| --- | --- | ---: | --- |
| 微光权杖 | 初始 | 免费 | 均衡的基础权杖 |
| 雷鸣权杖 | 第 4 关 | 180 | 雷击伤害 +35%，帕拉普通攻击 +15% |
| 霜纹权杖 | 第 8 关 | 240 | 寒霜伤害 +45%，减速延长 3 秒 |
| 祈愿权杖 | 第 13 关 | 300 | 生命祷言额外治疗 55，光环范围 +30 |
| 旅者之环 | 初始 | 免费 | 基础戒指，无额外增益 |
| 丰收之环 | 第 3 关 | 160 | 食物上限 +25、每秒恢复 +0.65 |
| 灵泉之环 | 第 6 关 | 210 | 魔法上限 +25、每秒恢复 +0.7 |
| 守望之环 | 第 11 关 | 280 | 帕拉最大生命 +90、光环范围 +25 |

原作的社区资料将装备分为提供主动能力的锤杖与提供被动效果的戒指；这里使用原创名称、美术和数值，将权杖做成现有三种魔法的专精选择。[参考资料：Paladog 装备条目](https://kongregate.fandom.com/wiki/Paladog)。

在同一个界面还可以升级营地强化。新存档初始拥有 120 金币；关卡首通获得完整金币奖励，再次通关获得该关奖励的 40%（向下取整），失败没有金币奖励。每项最多升级 7 次，后续升级价格逐步提高。

| 升级 | 每级效果 |
| --- | --- |
| 橡木之心 | 英雄最大生命增加 65 |
| 勇气旗帜 | 英雄与伙伴伤害增加基础值的 12% |
| 丰收口袋 | 每秒食物恢复增加 0.45，食物上限增加 10 |
| 星辰祝福 | 每秒魔法恢复增加 0.4，魔法上限增加 10，同时增强魔法效果 |

建议先解决当前失败的直接原因：英雄容易阵亡可升级橡木之心；部队不足可升级丰收口袋；火力不足可升级勇气旗帜或调整兵种比例。

游戏通过 `localStorage` 自动保存已完成关卡、最高星级、最佳通关时间、生存最佳纪录、金币、已购买与当前装备、升级和声音设置。通关、完成生存挑战、购买或切换装备、购买升级或切换声音后自动保存。**不会保存进行中的战斗**：刷新或关闭页面后，需要重新开始当前关卡或生存挑战。存档保存在本机当前浏览器中，不会上传到服务器，也没有账号或云端同步。

旧版 12 关存档会自动读取并保留金币、升级、星级与最佳时间；若此前已经完成第 12 关，新版会开放第 13 关。

- 更换浏览器、隐私模式、清理浏览数据或换一个网址，可能看不到原来的存档。
- 使用 `file://` 直接打开时，各浏览器对本地文件存储的行为不同；固定浏览器和打开方式更有利于保存进度。
- 如果浏览器禁止本地存储，可以继续体验战斗，但刷新或关闭后进度可能无法保留。
- 不建议为了排查声音问题而清除站点数据，清除操作可能一并删除进度。

## 7. 画面与声音

像素画面由本项目的绘制代码生成。音乐和音效由 `js/audio.js` 中的 Web Audio 振荡器、音量包络及原创音序实时合成，没有远程音频请求或音频下载。背景音乐现有营地、普通战斗、无尽生存和首领四个主题；每首包含较长的旋律段落、变化结尾、和声、低音与不同强度的打击乐，并随场景切换。

合成音量默认较小，避免战斗中过于嘈杂；密集命中音效做了触发间隔限制。切换到后台时声音调度暂停；营地音乐会在浏览器允许的情况下恢复，进行中的战斗则需先点击“继续远征”或“继续挑战”。可通过界面的静音控制关闭声音。

曾检索原作官方配乐的可用版本；找到的主要是玩家录音或游戏提取文件，没有找到明确允许将其重新打包进本项目的授权，因此本版本继续使用原创配乐。[玩家录音说明](https://mythzsgame.pixnet.net/blog/posts/4036668745)、[游戏提取音乐目录](https://downloads.khinsider.com/?page=38)。

如果听不到声音，先点击页面，再检查游戏静音、浏览器标签页静音和系统音量。某些浏览器恢复后台页面后仍要求用户再次点击。

## 8. 开发与验证

项目使用原生 HTML、CSS 与 JavaScript，渲染采用 Canvas，音频采用 Web Audio。常规脚本按入口页面的顺序加载，不依赖 ES module 服务器环境，因此可以直接打开本地 HTML。

主要文件：

- `index.html`：页面入口与脚本加载。
- `js/`：战斗模拟、关卡配置、绘制、界面与声音。
- `js/audio.js`：`Pala.Audio` 接口，包含 `unlock()`、`setMuted()`、`play()`、`startMusic()` 和 `stopMusic()`。
- `server.cjs`：可选的 Node.js 本地静态服务器，处理 MIME 类型、路径边界、URL 解码及目录入口。
- `tests/`：使用 Node.js 内建测试运行器的逻辑测试。

执行 `npm test` 运行测试。自动测试不能替代实际游玩：修改战斗数值后，应实测早、中、后期关卡；修改布局后，应检查常用桌面分辨率及触控布局；修改存档结构后，应检查已有存档能否读取。

调试时可打开浏览器开发者工具检查 Console。开发服务器控制台会打印本地访问地址；地址占用时会显示端口冲突提示。

## 9. Android 后续方案

当前交付物是电脑浏览器游戏，尚未生成、签名或测试 Android APK。已有 Canvas 和触控交互为后续迁移提供基础，但不代表已经完成 Android 应用。

可选路线是用 Capacitor 或自建 Android WebView 包装本地网页资源。开始迁移前应确认：

1. 在真实设备上检查帧率、文字和按钮大小、横屏布局及屏幕安全区。
2. 处理应用前后台切换、音频恢复、系统返回键和意外中断。
3. 确认本地存储在应用升级后保留，必要时增加存档导入导出。
4. 制作应用图标、启动页、应用标识、签名和构建流程。
5. 如果计划上架，准备商店信息并重新确认名称、视觉形象等知识产权问题。

这些是后续工作规划，不是本版本已经实现的功能。

## 10. 素材来源与使用边界

本版本不依赖素材站下载：像素角色、环境和界面由项目代码绘制，声音由项目代码实时合成。第三方品牌和原作名称仅用于说明灵感来源，相关权利归各自权利方。

`package.json` 当前标记为 `UNLICENSED`，表示项目未发布通用开源许可证；这不是对原作素材或商标的授权。未来公开发布前应由项目所有者确定代码和原创素材的授权方式与正式产品名称。
